20// EmissionDistribution provides a 3D pdf lookup table to sample a
21// point based on emission energy distribution.
22// Note the pdf it returns is not in 3D space but solid angle space,
23// which describes the accumulated pdf of sampling a direction wi
24// formed by connecting input p and sampled point
25// The reason for this is we integrate volume contribution in
26// solid angle domain instead of Cartesian domain
27// (the total emission energy contribution along the wi direction

102// Explanation about Dense vs Sparse Emission Distributions
103// There are a few things to understand first.
104//
105// 1) We need to get a 3D position from EmissionDistribution::sample,
106// so we need to be able to convert an index from the cdf to a 3D position
107// 2) EmissionDistribution::pdf takes a 3D position and performs a line integral in 3D space,
108// so we need to be able to convert a 3D position to an index into the cdf.
109// 3) The vast majority of entries in the DenseEmissionDistribution are 0 for VdbVolumes.
110// No entries in the SparseEmissionDistribution are 0.
111//
112// The SparseEmissionDistribution adds an indexing scheme so that we can convert
113// between a 3D position and a cdf index. For DenseEmissionDistribution, the index
114// in the cdf is equivalent to the 3D position.
115// That is the key difference between Dense and Sparse EmissionDistribution.
116//
117// EmissionDistributions generated from the Primitive class use DenseEmissionDistributions
118// because the data actually is dense.
119// EmissionDistributions generated from the VdbVolume class use Sparse or Dense EmissionDistributions
120// depending on how sparse the data is.
121// If using SparseEmissionDistribution, the VdbVolume creates a sparse histogram (no zeros)
122// and an array of indexes (to convert into 3D positions), and that drastically reduces
123// the memory of the EmissionDistribution.
124//
125// DenseEmissionDistribution uses the bounding box around the volume.
126// For VdbVolumes, the dimensions of the bounding box are voxels_wide * voxels_long * voxels_high.
127// That's the length of the float array for the cdf, which is filled in densely, mostly with 0s.
128// So we run out of memory quickly using that scheme.
129//
130// For volumes that are somewhat dense, the DenseEmissionDistribution is faster
131// because we don't have to do the extra conversion between 3D position and cdf index.
132
