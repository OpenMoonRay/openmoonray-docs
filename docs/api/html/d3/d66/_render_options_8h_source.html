36/**
37 * The RenderOptions contain common settings of interest to many parts of the
38 * renderer, such as the frame dimensions and output filename.
39 *
40 * Values are drawn from a variety of sources, including command line arguments,
41 * SceneVariables, and direct setting by renderer code.
42 *
43 * At the moment, options set via parsing the command line or setting them
44 * directly will override any equivalent settings in the RDL SceneVariables.
45 * In addition, there are last-ditch defaults for each option in case we have
46 * no suitable source to set it from.
47 *
48 * To add a new RenderOption, follow these steps:
49 * 1) Add a private member variable to this class, and initialize it to an
50 * "unset" (not default!) value in the constructor.
51 * 2) Add a getter and setter for the new variable. The getter should first
52 * see if the value is set and return it, otherwise look it up in the
53 * SceneVariables (if applicable). Finally, it should return a last-ditch
54 * default value. The setter should just be a trivial setter.
55 * 3) If the option can be overridden with a command line option, make
56 * sure to add some code for it in parseFromCommandLine(). Don't forget
57 * to add it to the usage message as well in getUsageMessage().
58 * 4) If the option must be settable by the MOONRAY infrastructure
59 * ConfigDictionary, you'll need to add the appropriate setter call in
60 * dso/computation/mcrt/McrtComputation.cc. The reason we don't handle that
61 * here is to avoid an infrastructure library dependency.
62 *
63 * That's it! You can now access the value of the option using the getter
64 * (always use the getter!) in any place we use the RenderOptions (right now
65 * the RenderContext, RenderDriver, moonray, and MCRT computation).
66 */
