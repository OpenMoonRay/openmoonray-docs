47/**
48 * A BinaryReader object can decode a binary stream of RDL data into a
49 * SceneContext. It can be used to load a SceneContext from a serialized file,
50 * apply incremental updates from a network socket, etc.
51 *
52 * Since BinaryReader needs to make modifications to the SceneContext, it
53 * cannot operate on a const (read-only) context. It must be used at a point
54 * where the SceneContext is mutable.
55 *
56 * The BinaryReader maintains no state other than the SceneContext it is
57 * supposed to modify, so keeping it around to apply multiple incremental
58 * updates to the SceneContext should work just fine.
59 *
60 * The BinaryReader can handle binary data from a number of sources. There are
61 * convenience functions for reading RDL data from a file or a generic input
62 * stream. These methods handle proper framing of the RDL binary data. The
63 * method which reads binary data directly from byte strings assumes the
64 * framing has already been removed and the appropriate manfiest and payload
65 * buffers have been extracted.
66 *
67 * RDL framing is very simple, so if you want to handle it at a higher level
68 * and read directly into byte strings it's not very hard. The frame looks
69 * like this:
70 *
71 * +---------+---------+------------+------------+
72 * | mlen | plen | manifest | payload |
73 * +---------+---------+------------+------------+
74 * | 8 bytes | 8 bytes | mlen bytes | plen bytes |
75 * +---------+---------+------------+------------+
76 * ^-- first byte last byte --^
77 *
78 * NOTE: Both mlen and plen are 64-bit unsigned integers, in network byte
79 * order (big endian).
80 *
81 * This encoding allows us to easily read the manifest and payload into
82 * separate buffers. The manifest must be decoded serially, but once decoded,
83 * we have offsets into each message in the payload, so we can decode it in
84 * parallel.
85 *
86 * Thread Safety:
87 * - The SceneContext guarantees that operations that the BinaryReader takes
88 * (such as creating new SceneObjects) happens in a threadsafe way.
89 * - Manipulating the same SceneObject in multiple threads is not safe. As
90 * such, a binary RDL file with multiple copies of the same SceneObject
91 * may cause thread unsafety in the BinaryReader if those updates are
92 * decoded in parallel. The BinaryWriter will never produce such files,
93 * but it's something to keep in mind.
94 * - Since the BinaryReader writes into SceneContext data (in particular,
95 * SceneObjects), it is not safe to be mucking about with that data in
96 * another thread while the BinaryReader is working.
97 */
