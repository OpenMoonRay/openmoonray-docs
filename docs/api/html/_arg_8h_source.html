110 //
111 // messages
112 //
113 // Arg object has several message output-related APIs.
114 // Basically, the Arg object maintains argument data for command-line parsing.
115 // From this point of view, it is a bit strange that the Arg object has a message output method.
116 // Why Arg has a message output method is because the Arg object is the best place to keep where is
117 // the destination of the message goes.
118 // For example, if the Arg object is constructed by an incoming command-line from tlSvr (telnet-server),
119 // we would like to send back all of the printout messages to the tlSvr client as well.
120 // This type of message destination information only is kept by the Arg object itself.
121 // And also, in most cases, the Arg object is the only argument for the parser action function.
122 // It is a little bit difficult to pass message output destination control information to the parser
123 // action function without using the Arg object itself.
124 // We can add a special message handler as well. You can design your own message output logic
125 // using setMessageHandler() API.
126 //
127 void setCerrOutput(bool flag) { mCerrOutput = flag; } // Message output condition for cerr

198inline bool
199Arg::isOpt(const std::string &name, bool caseSensitive)
200{
201 if (mArg.size() > 0 && cmpOpt(mArg[0], name, caseSensitive)) {
202 shiftArg();
203 return true;
204 }
205 return false;
