174 // ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ //
175 // We receive the mesh's vertex buffer in render space. However, we want to
176 // apply the light's local to world transform to the mesh light. The transform
177 // hierarchy breakdown goes like this:
178
179 // v : a vertex
180
181 // We'll use the following subscripts:
182 // W : world space
183 // R : render space
184 // G : the geometry's local space
185 // L : the light's local space
186
187 // So we have:
188 // vR : Input vertex buffer in render space
189 // vG : vertex buffer in geometry's local space
190 // G2W : geometry's local to world transform
191 // W2R : scene's world to render transform
192
193 // So the vertices we're given have been generated by this equation:
194
195 // vR = vG * G2W * W2R
196
197 // By definition, the light's transform is the parent of the geometry's transform,
198 // i.e. we need to apply the light's transform just after the geometry's transform
199 // in the sequence above. To do this, first we change the interpretation of the
200 // transformations in the above equation, replacing world space with the light's
201 // local space. The two spaces are identical at this point, because we haven't
202 // applied the light's transform, so this is just a renaming:
203
204 // vR = vG * G2L * L2R
205
206 // So this vR is what we are given. But what we want to compute is vR', the vertex
207 // position in render space having also applied the light to world transform L2W:
208
209 // vR' = vG * G2L * L2W * W2R
210
211 // Our task is to convert vR to vR'. To do this, first we invert the expression for
212 // vR to obtain an expression for vG:
213
214 // vG = vR * L2R^-1 * G2L^-1
215 // = vR * R2L * L2G
216
217 // and then substitute this into the expression for vR':
218
219 // vR' = (vR * R2L * L2G) * G2L * L2W * W2R
220 // = vR * R2L * L2W * W2R
221
222 // We already have vR, L2W and W2R. Now we just need to account for R2L.
223 // But this can be obtained by simply inverting W2R. The justification for
224 // this is that in the expression for vR, we've reinterpreted W2R as L2R,
225 // because vR had no light transform applied.
226
227 // We need to store the R2L, which is the scene's render to world transform.
228 scene_rdl2::math::Mat4d mRender2Light;
229 // ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ //
230
231 // Vertex buffer. Flat interleaved array. Different motion samples of the same vertex are next to each other in
232 // memory. Meshes are ordered one after another.
233 // Example: If there are 3 meshes, 2 motion samples, and the meshes have 2, 3, and 2 vertices respectively,
234 // the vertex layout looks like:
235 //
236 // mesh 0 | mesh 1 | mesh 2
237 // m0v0t0 m0v0t1 m0v1t0 m0v1t1 m1v0t0 m1v0t1 m1v1t0 m1v1t1 m1v2t0 m1v2t1 m2v0t0 m2v0t1 m2v1t0 m2v1t1
238 //
239 std::vector<scene_rdl2::math::Vec3f> mVertices;
240
241 // Geometry buffers. Per mesh.

291 // Called during sample operation. This traverses the bvh using the random
292 // number u. It uses the shadingPoint and shadingNormal to determine the
293 // probability of picking the left or right node (PL and PR). If u < PL,
294 // we traverse down the left side of the tree, otherwise we traverse down
295 // the right side. We terminate at a leaf node, which contains the index of
296 // a mesh face.
297 // During the traversal we compute the pdf by multiplying the probabilities of
298 // traversing each node. For example, the root node of the BVH has probability
299 // P = 1. If we traverse the left node, that is P *= PL. If we traverse the
300 // right node P *= PR. Once we have reached the leaf node, we have the pdf
301 // for that face.
302 // Returns index of the leaf node in the BVH.
303 int drawSampleRecurse(const scene_rdl2::math::Vec3f& shadingPoint, const scene_rdl2::math::Vec3f *shadingNormal,
