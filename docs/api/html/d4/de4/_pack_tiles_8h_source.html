10//
11// -- PackTile image buffer data encoding/decoding main logic --
12//
13// United States Patent : 11,182,949 : Nov/23/2021
14//
15// Basically, renderBuffer data is encoded to PackTile data based on delta coding with
16// several different compression ideas. This packTile data is created each buffer independently
17// and finally enqueued into one ProgressiveFrame message. ProgressiveFrame message is sent
18// from mcrt to mcrt_merge and also mcrt_merge to client.
19// Finally PackTile data is decoded and reconstructed original data.
20// One PackTile (also ProgressiveFrame message) only keeps one delta information.
21// In order to re-construct entire image, We have to track all delta PackTile data from beginning
22// in proper order.
23// This PackTile supports 3 different data precision and controlled by PrecisionMode parameter.
24// They are 32bit single float, 16bit half float and 8bit unsigned char precision.
25//
26// Based on my test scene (Timmy's bedroom), data size is 4x to 500x smaller than
27// PartialFrame message. And latency from mcrt to client (via mcrt_merge) is down from
28// 250ms to 37ms.
29//

68 // PackTile format version for encoding(i.e. enqueue) operation.
69 // We can encode (i.e. enqueue) both of VER1 and VER2 based on argument of enqFormatVer of
70 // encode*() Current default is VER2.
71 enum class EnqFormatVer : unsigned int {
72 VER1 = 1, // original naive tileId/pixelMask output version
73 VER2 = 2 // optimized tileId/pixelMask output by PackActiveTiles
74 };

76 enum class PrecisionMode : char {
77 F32, // using full 32bit float
78 H16, // using half 16bit float
79 UC8 // using 8bit uchar : clamp 0.0~1.0 and map into 0~255
80 };
