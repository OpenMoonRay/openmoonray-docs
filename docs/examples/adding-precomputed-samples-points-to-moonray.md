## Adding pre-computed samples points to MoonRay

Sample points should be floating-point values in \[0, 1). A value of 1
is an input error. Which sampling methods and which points are being
used are specified in
**moonray/lib/rendering/pbr/sampler/SamplingPreprocess.h**. Top-level sets
define the sampling methods for pixels samples, lens samples, time
samples, one-dimensional integrator samples, and two-dimensional
integrator samples. At this time, three-dimensional integrator samples
are only partially supported. Which set to use is specified as a
pre-processor directive as a compiler argument in the top-level
SConscript (**moonray/SConscript**).

Pre-computed points f or pixel and lens samples are, by default,
stored in separate 2D grids (USE\_PARTITIONED\_PIXEL\_2D and
USE\_PARTITIONED\_LENS). Time samples are stored in a specially
partitioned array. One-dimensional and two-dimensional samples are
stored in contiguous arrays (`std::vector`). The pixel and lens samples
are stored in the file in progressive order. The integrator samples
are hard coded to have 4096 independent sequences of 1024 samples
each, implying that the one-dimensional integrator sequences contain
`4096\*1024` floating-point values, while the two-dimensional integrator
sequences contain `4096\*1024\*2` floating-point values. The points are
stored per sequence in progressive order. For example,
for a two-dimensional integrator sequence, the first point of
sequence two has array indices `4096 \* 1 + 0` and `4096 \* 1 + 1`.

## Testing ASCII point files

The ASCII file format is whitespace-separated floating-point values in
\[0, 1). ASCII should only be used for testing. In
**moonray/lib/rendering/pbr/sampler/ [Sampler.cc]**, there is a function named
`containerFromFile`, which will create any of the containers listed
above.

## Adding binary point files

To move points into a release, they must be converted to binary,
compiled into ELF format, and linked into MoonRay. The point-generation suite has a program that will do the conversion from ACII
to the binary format. The pbr SConscript
(**moonray/lib/rendering/pbr/SConscript**) converts the binary file to ELF
format, and the binary files must be listed here.

**Binary details**

The binary points file simply stores the array of floating-point
values in binary format. The Linux command objcopy will be used in the
SConscript to convert the files to the ELF format and add symbols
which we can use to read the array after we link to the ELF obj file
created by objcopy. I have not spent a lot of time figuring out how to
specify the symbol names generated by objcopy and tend to use readelf
to find the generated symbol names.
